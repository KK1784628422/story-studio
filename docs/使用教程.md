## 1. 准备什么

| 需要 | 说明 |
|---|---|
| Node.js **≥ 22** | `node -v` 检查。低于 22 会启动失败 |
| pnpm | `npm i -g pnpm` |
| 一个模型 API key | **自备**。任意 OpenAI 兼容端点都行（DeepSeek / Kimi / GLM / Qwen / 各类网关） |
| 磁盘空间 | 依赖约 800MB（主要是 Electron）；书稿本身很小 |

模型选型建议：长篇创作上下文会迅速涨到几十万 token，优先选支持 **prompt caching** 的端点
和上下文窗口 ≥ 256k 的模型，成本差别很大。故事创作推荐 temperature 1.1~1.3。

## 2. 安装与启动

```bash
git clone <仓库地址> story-studio
cd story-studio
pnpm install
```

### 配置环境变量

```bash
cp .env.example .env
```

打开 `.env`，至少填这三项（`STORY_STUDIO_API_KEY` 填**你自己的** key）：

```ini
STORY_STUDIO_MODEL_BASE_URL=https://api.deepseek.com/v1
STORY_STUDIO_API_KEY=sk-你的key
STORY_STUDIO_MODEL_ID=deepseek-v4-pro
```

`STORY_STUDIO_WORKSPACE` 可以先留空——启动后会有欢迎页让你选目录。

### 启动

```bash
pnpm build     # 构建前端（首次必做，否则页面是空的）
pnpm dev       # 启动服务
```

终端会打印服务地址（默认 `http://127.0.0.1:8100`），浏览器一般会自动打开。

⚠️ **改了前端代码后要重新 `pnpm build`**，或者用下面的开发模式（Vite 热更新，改完即生效）：

```bash
pnpm dev        # 终端 1：后端
pnpm dev:web    # 终端 2：前端 HMR → http://127.0.0.1:5173
```

### 桌面模式（可选，推荐）

```bash
pnpm dev:desktop
```

桌面模式（Electron）多出来的能力：

- **内嵌 Agent 浏览器**：扫榜、网页 AI 生图都在应用内的独立浏览器里跑，**不会碰你的系统浏览器**，
  而且过程可视化（右侧面板能直接看到页面）。
- 音乐播放器可悬浮置顶、无边框标题栏。

纯 Web 模式下要抓需要登录态的站点，才需要另开一个 9222 调试端口的 Chrome，届时应用会先征求你同意。

## 3. 配置模型（必做）

有两种方式，任选。

### 方式 A：`.env`（最简单）

就是上面填的那三项，启动即生效。

### 方式 B：应用内「模型设置」面板（功能更全）

点左侧栏底部的**模型设置**，可以配多个 Provider 并在输入栏切换。每个 Provider 可单独设置：

| 配置项 | 说明 |
|---|---|
| 名称 / 端点 / 模型 ID / API key | 基础四项 |
| 上下文窗口 | 不填则按模型 ID 自动识别容量；长篇建议显式填（快捷档 128k / 256k / 512k / 1M） |
| 输出上限 | 写长章建议 32768；默认 16384 |
| 支持图片输入 | 模型能不能读图（默认不支持） |
| 采样参数 | Temperature / Top P / Top K。小说创作推荐 T 1.3 / P 0.95；TopK 多数端点不支持，建议留空 |

**免费池**：如果同一个端点你有多个免费账号的 key，填多个 key 会自动轮询——
某个 key 被限流（429/503）时自动换下一个重试，对话不中断。

### key 存在哪

- `.env` —— 你的环境变量配置
- `.local/settings.json` —— 面板里配的 Provider

**这两个都已被 `.gitignore` 排除。** 分享目录、截图、提 issue 前请先确认不要把这两个文件带出去。

## 4. 创建第一本书

启动后先进**欢迎页**，两个选择：

- **打开小说文件夹** —— 选一个已有的书目录（已有 `正文/`、`大纲/` 等结构的）
- **新建小说** —— 建一个空的书目录，从零开始

选完进入工作台。之后切换书用左侧栏底部的**书架**（会记住你打开过的书）。

书目录的结构见[附录](#10-附录书目录结构)——不用记，Agent 会按规范自动建。

## 5. 认识界面

工作台是四栏布局：

```
┌─ 顶栏：书名 / 设置 ────────────────────────────────────────┐
│ 模式栏 │ 会话侧栏 │  聊天区（主战场）  │ 工作面板         │
│ 9 个模式│ 历史会话 │  流式输出/工具卡/  │ 可视化/文档/浏览器│
│        │         │  审批卡/问答表单    │                 │
├─ 状态栏：连接状态 / 上下文占用 / 日志 ────────────────────┤
```

**模式栏**（左侧竖排）是 9 个创作模式，点一下切换。切入模式会同时改变：系统提示词、
可用技能、可用工具、写入是否需要审批、右侧默认打开哪个面板。

> 💡 你也可以不点模式栏，直接说需求——比如「帮我看看第 12 章有没有问题」，
> 本地意图路由会自动切到审稿模式。识别不确定时会走一次轻量 LLM 兜底分类。

**工作面板**（右侧）有三档，用面板顶部的按钮切换：

| 档位 | 用途 |
|---|---|
| 可视化 | 大纲 / 设定 / 追踪的卡片墙，含**人物关系网**图谱 |
| 文档编辑 | 富文本编辑 Markdown 文件（正文、设定等） |
| Agent 浏览器 | 桌面模式下内嵌的浏览器，看 Agent 在访问什么页面 |

**聊天区**里会出现这几种卡片：

- **工具卡** — Agent 调用了什么工具、参数、结果（可折叠）
- **审批卡** — 需要你点头的写操作。卡里带完整 diff，可以逐处确认
- **门禁卡** — 写正文后质检没过，会红着告诉你哪几条不过
- **问答表单** — Agent 需要你补充设定时，会给你一张结构化表单填
- **交付卡** — 章节写完的成果确认

## 6. 完整走一遍：从开书到第一章

### 6.1 开书

直接说：

```
帮我开书
```

（「开书」是确定性路由词，会自动切到**创作**模式。你也可以先切模式再说。）

Agent 会加载长篇写作技能，走三个阶段：

1. **Phase 1** 建项目、确认选题
2. **Phase 2** 核心设定（世界观、力量体系、角色、关系）
3. **Phase 3** 卷纲 + 首批 10 章细纲

> ⚠️ **它会停在细纲交付，不会自动往下写正文。** 这是刻意的——开书的产出是「可评审的细纲」，
> 你看过认可了，再让它写。

这个阶段 Agent 会问你很多问题（题材、主角、金手指、情绪基调）。认真答，这些答案会变成
`设定/` 下的文件，之后每章写作都会读它们。涉及写入设定文件时会弹审批卡。

如果你还想先聊聊方向再动笔，用**讨论**模式——那里写入设定/大纲前一律先弹审批，
不会默默落盘。

**产出物**（在书目录里）：`设定/世界观/`、`设定/角色/{角色名}.md`、`设定/关系.md`、
`设定/题材定位.md`、`大纲/大纲.md`、`大纲/卷纲_第一卷.md`、`大纲/细纲_第001章.md` … 共 10 章细纲。

其中 `设定/关系.md` 里的**关系总览表**要保证格式正确——前端的人物关系网是逐行解析这张表的，
表缺了或格式不对，图谱就是空的。

### 6.2 写第一章（创作模式）

细纲确认后，切到**创作**模式，说：

```
写第1章
```

Agent 会走单章闭环：读细纲 → 读追踪上下文 → 写前准备 → 写作 → 质检 → 提交追踪事务。

正文会**落盘**到 `正文/第001章_章名.md`——它不会只在聊天里给你一段文字。

### 6.3 质量门禁：这一步会拦你

写正文文件时，系统自动触发**质量门禁**：

```
写前快照（保留最近 5 版）
  → 标点归一（唯一允许改写你文件的脚本）
  → 三个只读检测并行跑：
       check-ai-patterns   AI 味句式、禁用词、啰嗦句式
       check-outline-copy  细纲原文照搬超过阈值
       check-degeneration  复读、截断、元信息泄漏
  → 全部 exit 0 才算 PASSED
```

只要有 **blocking** 项，Agent 会收到详细报告并**定点修复重写**，最多重试 3 次；
3 次还不过就停下来找你人工处理。**blocking 清零之前，它不会跟你汇报"章节完成"。**

细纲文件走的是轻量门禁（只跑退化检测），因为细纲的字段本来就不是正文文风。

如果你手动在编辑器里改正文保存，会跑一次只读检查但不强拦——你自己的稿子你说了算。

> 作者手动确认过的版本会被登记为免检；一旦内容又变了，门禁自动恢复。

### 6.4 追踪事务：为什么它在意"一致性"

质检通过后，Agent 会提交一个**追踪事务**，把这章发生的变化合并进四类状态：

| 状态 | 内容 |
|---|---|
| characters | 角色当前快照（位置、状态、实力、关系） |
| foreshadow | 伏笔：埋了什么、回收了没有 |
| timeline_events | 时间线事实 |
| context | 续写状态卡（下一章从这儿接着写） |

`追踪/` 下的派生视图（角色状态、伏笔视图、时间线、续写状态卡）由脚本**原子生成**，
不允许手改——手改会导致状态漂移，下一章的上下文就是错的。

**一章真正"完成"的判定 = 门禁通过 + 追踪事务提交成功。** 两个都过了才算完。

### 6.5 日更续写

有了正文和追踪之后，日常就是：

```
日更3章
```

或者更精确地控制：

```
只写1章
逐章确认
继续写第 15-17 章
```

单轮建议不超过 3 章，每 3 章 Agent 会跑一次追踪快照汇报，方便你及时纠偏。

改稿则是另两条路（在**优化**模式）：

```
第 12 章太啰嗦了，帮我精简
第 12 章提高一下文笔质感
```

前者走去 AI 味流程（跑质检、卡字数下限），后者走升华流程（不跑质检，只读细纲 + 本章 + 前一章，
一次到位改写，然后停在审批卡等你确认）。升华后的版本会被登记为「作者已确认」，之后不再参与门禁。

## 7. 九个模式怎么选

| 模式 | 什么时候用 | 典型说法 |
|---|---|---|
| **讨论** | 聊方向、聊剧情、改设定（写入前必审批） | 「这个设定你觉得怎么样」「主角动机再想想」 |
| **创作** | 开书 + 写正文（核心） | 「帮我开书」「写第1章」「日更3章」「继续写」 |
| **导入** | 把别处写的稿子搬进来 | 「这是我用别的 AI 写的，帮我导进来」 |
| **优化** | 去 AI 味、润色、大修 | 「太像AI写的了帮我改改」「第20章回炉」 |
| **审稿** | 多视角体检 | 「帮我审一下前 30 章」 |
| **市场** | 扫榜、拆解对标书 | 「最近什么题材火」「拆一下这本书」 |
| **预览** | 纯阅读 / 听书，不调用模型 | 直接点开右侧阅读器 |
| **同人** | 基于原著写衍生 | 「写全职法师同人」（换成你要写的原著） |
| **校准** | 长篇写久了设定打架，做一致性体检 | 「检查一下我的设定对不对得上」 |

几个要点：

- **审稿模式在工具层面就没有写文件的能力**，报告只能通过 `save_report` 落到
  `.story-studio/reports/`，右侧报告面板实时可见。所以"审稿顺手改了正文"这件事不可能发生。
- **导入 / 优化 / 同人 / 校准**模式下，改写已有文件必须审批，新建文件放行——
  避免"刷审批卡"，但绝不静默覆盖你的原稿。
- **市场模式**扫榜用确定性采集脚本。起点这类 SSR 站点直接 HTTP 直采；番茄/七猫/晋江/刺猬猫
  需要 JS 渲染或登录态，会走内嵌浏览器。爬虫受平台反爬影响，失败是常态，不影响其他模式。

### 同人模式的四步

同人模式是完整的一套独立流程（适合基于既有原著创作）：

1. **设定** — 联网检索原著世界观/势力/角色，逐项确认后落盘到 `原著/`；再答 15 问问卷生成同人侧设定
2. **拆书** — 上传原著原文（单卷 ≤2MB），Agent 按**事件桥段**粒度做摘要（一卷约 4-8 个桥段，不是一章一个）
3. **卷纲与细纲** — 在面板上点选原著时间线上的**分岔点**，之后同人剧情从这里展开
4. **创作** — 交接给创作模式，复用 13 步单章闭环

进度存在 `原著/_progress.json`，随时可以新开会话说「继续同人」从断点恢复。
面板和 Agent 都会写这个进度文件，所以**不要手动改它**。

## 8. 阅读与写作辅助功能

| 功能 | 位置 | 说明 |
|---|---|---|
| **手机仿真阅读器** | 预览模式 / 右侧面板 | 自研分页算法，三套主题、字号可调，进度本地记忆 |
| **听书** | 阅读器内 | Edge TTS，6 种中文音色，逐句高亮，自动预取下一页/下一章 |
| **人物关系网** | 可视化面板 | 解析 `设定/关系.md` 的关系总览表画图谱，支持上传角色头像 |
| **追踪面板** | 可视化面板 | 角色状态 / 伏笔 / 时间线 / 逐章记录 四个页签 |
| **执行画布** | 创作模式右侧 | Agent 干活时节点实时生长，能看到它在跑哪一步 |
| **报告面板** | 审稿/校准模式右侧 | 审稿报告、诊断报告，点击可跳转到正文对应位置 |
| **音乐播放器** | 独立浮层 | 需自己配置音乐源；未配置时不显示 |
| **桌宠** | 聊天区 | 随 Agent 状态变表情（思考/打字/提问/成功/失败），可在设置里关掉 |
| **Token 统计** | 顶栏胶囊 / 设置 | 每次任务的输入输出 token、缓存命中率、耗时 |

## 9. 常见问题

**启动后页面空白 / 打不开**
先确认跑过 `pnpm build`。开发时用 `pnpm dev:web` 走 5173 端口。

**提示未配置 API key**
`.env` 里 `STORY_STUDIO_API_KEY` 没填或填错。也可以在应用内模型设置面板里配。
终端启动日志里会打印 `API key 已配置 / !! 未配置`。

**模型报 401 / 403**
key 不对或没有这个模型的权限。检查 `STORY_STUDIO_MODEL_BASE_URL` 和 key 是不是同一个服务商的。

**模型报 404**
端点地址写错了。注意 base URL 通常要带 `/v1`。

**模型报 429 / 使用人数太多**
限流。免费池（配多个 key）会自动换 key 重试；单 key 的话等一会儿或用付费端点。

**一直提示 "Request is missing x-opencode-session"**
你用的是 opencode 网关，应用已自动注入所需请求头。如果仍报错，把应用更新到最新版。

**GATE FAILED 反复出现**
门禁报告里会列出具体是哪条规则、哪句话。可以：
① 让 Agent 继续按报告定点修；② 直接说「这句我不想改，按我的来」——你手动确认后该版本登记免检。

**提示「技能 story-long-write 未加载」**
`packages/skills/vendor/` 目录缺失或不完整。从上游同步一次：

```bash
pnpm sync-skills
# 或指定源目录
STORY_STUDIO_SKILLS_SOURCE=/path/to/oh-story-claudecode/.agents/skills pnpm sync-skills
```

⚠️ `sync-skills` 是**全删重建**，运行前先 `git status` 确认干净。

**看不到日志 / 想知道 Agent 到底卡在哪**
右侧状态栏能打开日志抽屉；完整日志在 `logs/chat.log`（按 10MB 自动轮转，保留 3 份）。

**扫榜失败**
平台反爬。起点可直采，其他站点失败属正常，不影响创作功能。

**关系网是空的**
`设定/关系.md` 缺「关系总览」表格，或表格格式不对。表格前两列必须是纯角色名，
且与 `设定/角色/{角色名}.md` 文件名一致。

## 10. 附录：书目录结构

Agent 会按这个规范自动建目录，你不用手动创建，但知道结构有助于排查：

```
{书名}/
├── 设定/
│   ├── 世界观/        背景设定.md、力量体系.md …
│   ├── 角色/          每个人物一个文件，文件名 = 角色名
│   ├── 势力/          每个组织一个文件
│   ├── 关系.md        含「关系总览」表格 → 驱动前端关系网
│   ├── 题材定位.md    题材核心梗 + 对标分析 + 终局底牌
│   └── 题材正文提示卡.md  边界/期待/爽点/节奏/禁漂移
├── 大纲/
│   ├── 大纲.md        全书卷级结构
│   ├── 卷纲_第一卷.md  对标坐标 + 剧情单元 + 情绪弧线 + 伏笔 + 反转
│   └── 细纲_第001章.md 每章一个：章节定位 + 事件 + 钩子 + 爽点 + 悬念
├── 正文/
│   └── 第001章_章名.md   ← 写这里会自动触发质量门禁
├── 对标/{对标书名}/   扫榜拆文的产出（原文、角色、剧情、设定、拆文报告）
├── 追踪/              四类一致性状态 + 派生视图（受保护，别手改）
└── .story-studio/     快照历史 / 报告 / 临时稿 / 审批指纹
```

**命名约定**：正文章节 `第NNN章_章名.md`（三位补零），细纲 `细纲_第NNN章.md`。
这套命名是门禁识别的依据——`正文/*.md` 触发完整门禁，`大纲/细纲_*.md` 触发轻量门禁。
