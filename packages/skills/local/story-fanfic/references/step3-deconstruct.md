# 第 2 步：拆书（逐卷拆解原著原文）

> 四步制中本文件对应第 2 步；文件名保留 step3 仅为历史一致。

目标：把用户上传的原著原文（单卷 ≤2MB/约 60 万字）按**事件桥段**摘要（每卷约 4-8 段，如 120 章原著 ≈ 5-6 次），聚合出该卷时间线与角色发展，供同人创作对照。**这是忠实还原原著的核心步骤。**

## 1. 前置检查

- 原著/原文/ 已有本卷文件（前端上传后聊天会收到系统消息；也可 ListFiles 确认）；

- 没有原文时引导用户：「请在右侧同人面板上传本卷 TXT（单文件不超过 2MB），或直接把文件路径发我。」

## 2. 边界识别（确定性脚本，不落章节文件）

```
node scripts/split-source.js --input 原著/原文/第一卷.txt --volume 1
```

- 脚本只产出 `原著/拆书/第1卷/边界.json`——每章 `{no, title, startLine, endLine}`（行号 1 起含），**不把章节复制进工作区**（原文已在 原著/原文/，拆书直接按行号读原文，无需中间切片文件）。

- 拿到 stdout 章数后，Edit \_progress.json 回填本卷 chapters 并置 status='in\_progress'。

- **幂等**：边界.json 已存在拒绝重跑（--force 仅升级旧格式重写边界，摘要不动）。

- **历史兼容**：旧版本的 章节/ 切片目录已废弃——存在时忽略（不读、不补），按边界.json 直读原文即可；用户可能已删除。

- **绝对禁止**自己 Write 章节切片文件（`章节/第NNN章_*.md`）——需要读原文时用 Read 工具的 offset/limit 按边界行号读，不要往工作区复制原文。

## 3. 桥段摘要（事件级桥段；禁止逐章写摘要）

摘要粒度是**事件**，不是单章也不是整篇。**绝对禁止一章一个摘要文件、一章一次确认。** 目标：每卷约 4-8 个事件桥段（120 章原著 ≈ 5-6 次）。

- **桥段划分（优先级从高到低）**：

  1. **分段表事件展开（首选）**：读 原著/原著信息.md 的「段落 章节 摘要」分段表，取与本卷章节范围相交的行，**把每行「摘要」列按顿号/逗号拆成事件序列**——每个事件一个桥段。示例：分段表「〈段落甲〉1–89 ｜ 事件一、事件二、事件三、事件四」→ 拆出 4 个事件桥段（事件一 / 事件二 / 事件三 / 事件四）+「〈段落乙〉90–120」拆出 2 个（事件五 / 事件六）→ 第 1 卷共 6 个桥段。

     - **事件章节定位**：分段表只给事件名不给章节号——读切片 边界.json 的章节标题，按标题语义匹配各事件的起止章（如「第7章 〈章节标题〉」对应事件一尾声、「第40章 〈章节标题〉」对应事件二起点）；标题定位不了的抽样 Read 1-2 章验证；仍不明确的事件边界按均分估。

     - **粒度微调**：单事件 <5 章的并入相邻事件（同段内优先）；单事件 >35 章的拆「（上）（下）」。
  2. **章节标题分界（次选，无分段表时）**：读 边界.json 的章节标题，按剧情单元切。
  3. **公式兜底**：桥段数 = 卷章数 ÷ 25 四舍五入（下限 3、上限 8），按固定章数均分。

- **处理方式（直读原文）**：一个桥段一次处理——按边界.json 取桥段首章 startLine 与末章 endLine，用 Read 读原文区间：`Read 原著/原文/{卷文件}.txt offset={startLine} limit={endLine-startLine+1}`（行数 ≤8000；超长桥段分多次 Read 续读）→ 下一响应 Write 一个桥段摘要文件（2 个 step/桥段）。**禁止把原文章节复制/落盘到工作区。**

- **文件命名**：`原著/拆书/第{V}卷/摘要/第NNN-MMM章.md`（NNN=桥段首章、MMM=末章，三位补零）——文件名即覆盖区间，是进度与断点的解析依据。

- **断点真值 = 桥段摘要文件覆盖的章节区间**：开工先 ListFiles 摘要目录，按文件名算出已覆盖章号集合，缺口即待处理桥段（不信任 \_progress 里的 summarized 计数）。

- **单会话上限 3 个桥段**：到上限主动收尾，汇报进度并建议新开会话（「继续同人」从断点续拆）。

- **桥段摘要模板**（每桥段 600-1500 字，只记影响后续连续性的信息，不复述文采）：

```md
# 第{NNN}-{MMM}章 摘要（{事件名，如：事件二}）

- 覆盖章节：第{NNN}章 - 第{MMM}章
- 所属段落：（源自 原著信息.md 分段表，如：〈段落甲〉）
- 段落概要：（该事件在分段表摘要列中的原文短语，如：事件二）
- 故事时间：（原文明示则照抄；未明示则「约第{前章}章后 N 天」）
- 主要地点：
- 出场角色：
- 关键事件：（按发生序列出，**每条带章号**，如「第041章 〈章节标题〉」）
- 角色变化：（角色名：状态/实力/关系变化 + 章号；无则「无显著变化」）
- 新增设定：（世界观/势力/物品/关系的新揭示；无则省略）
- 伏笔与回收：（带章号；无则省略）
```

## 3.5 旧单章摘要归并（强制脚本，开工第一步）

**铁律：摘要目录里已有的文件形态会诱导你模仿——看到** **`001章_标题.md`** **这类单章文件时，绝对禁止继续按单章粒度写新摘要。** 归并必须用确定性脚本，不要手工合并：

```
# 第一步：检测（发现单章文件 → exit 1 列出清单）
node scripts/merge-summaries.js --volume 1 --check

# 第二步：按事件计划归并（--check 报错后执行）
node scripts/merge-summaries.js --volume 1 --segments "1-36:事件一,37-61:事件二,62-89:事件三"
```

- **分段计划来源**：原著信息.md 分段表本卷各行的摘要列按顿号拆事件（第 3 节事件展开规则）+ 读 边界.json 章节标题定位各事件起止章；<5 章的小事件并入相邻事件命名（如「事件一与事件二」）。

- 脚本行为：区间内单章文件按章号拼接为 `第NNN-MMM章.md`（原 H1 降级为 `## 第N章` 小节，内容零丢失）、删除原单章文件；不在任何计划段内的单章文件会在结尾报错列出——补充分段重跑直到 --check 通过。

- **--check 通过后才允许继续拆书**（写新的区间摘要文件）；每个桥段摘要写完后、以及会话收尾前，再跑一次 --check 自查防止粒度回退。

- 归并产物头部有「说明」行标注由脚本归并——后续会话按桥段模板补全细化（故事时间/地点/角色变化等可在整段重写时统一整理），不阻塞流程。

## 4. 卷聚合（全卷摘要完成后）

读全部摘要（不回读原文）聚合三件产物：

**① 时间线.md**——本卷事件按序表：

```md
# 第{V}卷 时间线

| 故事时间 | 事件 | 出场 | 章节 |
|----------|------|------|------|
| 〈原著历法〉春 | 主角获得核心能力 | 主角、〈配角名〉 | 第1-3章 |
```

故事时间用原著自历法；未明示时间用相对表述（「主角入学后第 3 天」）。**严格保持 4 列表格**——面板在第 2 步卷详情解析本表供用户点选同人分岔点（写入 volumes[].forkEvent），列序变化会破坏解析。

**② 角色发展.md**——每角色一节：

```md
## {角色名}
- 卷初状态：（承接上卷或首次出场设定）
- 关键转折：（带章号，按序列出改变其状态/实力/关系的事件）
- 卷末状态：
```

同时把每个角色的卷末状态用 Edit **增量追加**到 原著/角色/{角色名}.md 的「## 原著发展史」节（每卷一小节 `### 第{V}卷`；改既有角色卡触发审批停靠是预期行为——用户应把关原著资料的写入）。

**③ 总结.md**——300-500 字卷概要 + 本卷时间线覆盖范围（起止）。起止写入 \_progress.json 该卷 timelineThrough（如「〈原著历法时间〉 → 〈原著历法时间·后段〉」）。

## 5. 卷确认停靠

ask\_confirm：「第 {V} 卷拆解完成：{章数} 章，时间线覆盖 {timelineThrough}。本卷故事时间发展线是否满足需求？确认后请在面板本卷详情的「时间线」页签点选同人分岔点（第 3 步卷纲将据此展开）。」

- 满足 → Edit \_progress.json：该卷 status='confirmed'（用户在面板点「确认本卷拆书」效果相同——面板接口直接落盘，无需重复写）；

- 不满足 → 用户指出缺失（如某角色发展没跟上/某事件遗漏）→ 回读对应章节补正摘要与聚合 → 重新确认。

**手动下一步（面板入口，优先于 ask_confirm 停靠）**：用户可在面板点某卷的「确认」按钮（接口直接写 volumes[].status=confirmed，缺 时间线.md/角色发展.md/总结.md 时会聊天通知你补齐），确认后点「进入第 3 步」由面板接口推进 step。用户也可在聊天里发「我确认第 X、Y 卷的拆书内容已足够支撑同人……手动进入下一步」类消息——此时：① 所选卷缺聚合产物则先按第 4 节补齐；② Edit \_progress.json 把这些卷 volumes[].status 置 'confirmed'；③ step 置 3，随即按第 3 步开始问询本卷内容/字数/时间线锚点。

## 6. 时间线溢出与后续卷

- 创作期间（第 4 步）剧情时间逼近已确认卷的 timelineThrough 时按 SKILL.md「时间线溢出」处理；

- 循环拆书：用户回第 2 步上传下一卷原文 → 重复本步全流程（volume 递增）；

- **每次拆书会话开始时**：确认 \_progress.json 中 s2.volumes 与 原著/原文/ 清单一致（面板上传新卷会自动登记），从摘要缺口续拆。
