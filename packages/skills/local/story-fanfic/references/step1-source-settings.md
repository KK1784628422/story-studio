# 第 1 步：统计原著设定

目标：联网检索 + 用户纠偏，产出经用户逐项确认的原著设定四件套，写入 原著/。

## 1. 获取基本信息

- 优先来源：用户在**同人面板欢迎页**填写并发来的原著信息（书名/作者/总字数，聊天消息里已含）；

- 缺项（用户只在聊天里说书名）→ 用 ask\_questions 补问作者与总字数（选填）。

## 2. 检索策略（两轮搜索）

**第一轮：自由搜索广撒网。** 依次搜（每次一个关键词，搜不到再换）：

- `{书名} 世界观 设定`

- `{书名} 力量体系 等级`

- `{书名} 势力 组织`

- `{书名} 角色 人物介绍`

- `{书名} 剧情梗概 结局`

**第二轮：定向搜索补细节。** 按系统提示词中「同人搜索源」清单逐站补全：

- `web_search` 加 `site:` 限定（如 `{书名} 人物 site:zh.moegirl.org.cn`、`{书名} 魔法体系 site:baike.baidu.com`）；

- 搜索命中后用 `web_fetch` 抓百科/设定站详情页，逐段提取；

- 贴吧/B站命中时抓专栏/资料整理帖的正文。

**信息处理纪律**：

- 两轮仍缺的细节，如实告知用户「未检索到，请补充或授权按同类作品惯例处理」，**不得编造**；

- 不同来源矛盾（如角色实力描述不一致），两个版本都保留并在展示时标注来源让用户裁定；

- 检索到的信息按「世界观 / 势力 / 角色 / 其他」四类暂存整理。

## 3. 四项逐一确认（草稿先行，面板展示）

**核心纪律：确认内容一律先写入 原著/草稿/ 下的草稿文件，不要只在聊天里展示。**
右侧同人面板会全文展示草稿（默认展开，用户无需在聊天里翻折叠块），并提供「确认落盘 / 有偏差」快捷按钮——你的确认问询要围绕这个面板流程展开。

四项按固定顺序推进，每项：

1. **写草稿**：把该项整理结果 Write 到 `原著/草稿/{项名}.md`（新文件放行，不触发审批）：

   - `原著/草稿/原著信息.md`：书名/作者/总字数/时间线跨度/主要检索来源；**全书分段摘要表（核心资产，见下）**

   - `原著/草稿/世界观.md`：背景设定 + 力量体系（等级划分/晋升方式/战力标尺/已知上限）

   - `原著/草稿/势力.md`：完整势力清单（每势力定位/实力档次/代表人物）+ 势力关系图谱文字版

   - `原著/草稿/角色.md`：主要角色静态卡（主角团/核心对手/剧情关键人物，一般 10-25 个）——**终局实力、结局状态、性格标签、OOC 红线**（全书完结视角，标注「实力不再变化」）
2. **聊天里只发简讯**：一段 ≤200 字的要点概览 + 「完整内容已写入右侧面板的待确认设定草稿，请查看后确认」（不要把全文贴进聊天）；
3. **等确认**：ask\_confirm 问「{项名}是否符合原著？」——用户也可能直接点面板按钮发送确认/偏差消息，同样有效；
4. **偏差循环**：不符 → 按用户指正继续定向搜索/修正 → **重写该草稿文件**（Edit 更新，审批卡是预期停靠）→ 再确认。

四项全部确认后（用户点面板「确认符合，正式落盘」或逐项确认均可）→ 执行第 4 节正式落盘。

**注意**：草稿文件是面板展示的载体，内容要完整详实（用户以此为判定依据）；但每份控制在 8KB 内，超长精简次要信息（**唯一例外：全书分段摘要表不许精简**）。

## 3.1 全书分段摘要表（原著信息.md 的核心资产）

联网检索常能拿到原著的**全书剧情分段总表**（百科词条/维基剧情节选多为此形态），三列结构：

```md
| 段落 | 章节 | 摘要 |
|------|------|------|
| 〈段落甲〉 | 1–89 | 事件一、事件二、事件三、事件四 |
| 〈段落乙〉 | 90–120 | 事件五、事件六 |
| ...（全书所有段落，逐行保留） | | |
```

**处理纪律**：

1. 检索到该表 → **完整逐行保留**进 原著信息.md（不许精简、不许只留前几行）——它是「预拆好的全书时间线骨架」；
2. 没检索到 → 可主动搜「{书名} 剧情分段 / 各卷内容 / 分卷介绍」再试一次；实在没有就不造（不得编造章节范围），留给第 2 步拆书自行划段；
3. 表的用途（下游协议都依赖它）：

   - **第 2 步拆书**：桥段划分第一优先级 = 表中本卷各行的「摘要」列**按顿号/逗号拆成事件序列**（每事件一个桥段，agent 读章节标题定位起止章；见 step3-deconstruct.md）——不是整行当一段；

   - **时间线溢出判断**：未拆到的章节，分段表可作粗略时间线参考；

   - **第 3 步时间线对比**：原著轨的章节级依据。

## 4. 落盘（用户确认后：草稿转正）

草稿按目标位置拆分转正（势力/角色按一文件一个的规范拆分），写完后**删除 原著/草稿/ 下的对应草稿文件**（Bash `rm` 或等价方式；面板的待确认区随之消失）：

| 草稿      | 转正目标                   | 模板要点                                                                 |
| ------- | ---------------------- | -------------------------------------------------------------------- |
| 原著信息.md | 原著/原著信息.md             | 首行 `> 来源：原著设定（联网检索，{YYYY-MM-DD} 用户确认）`；书名/作者/总字数/连载平台/时间线跨度/主要检索来源列表 |
| 世界观.md  | 原著/世界观.md              | 同上来源标签行；「背景设定」「力量体系」两大节                                              |
| 势力.md   | 原著/势力/{势力名}.md（每势力一文件） | 定位/实力/代表人物/对外关系；势力过小可并入世界观.md 的「势力杂记」节                               |
| 角色.md   | 原著/角色/{角色名}.md（每角色一文件） | 基本信息/身份定位/终局实力/结局状态/性格要点/OOC 红线；预留「## 原著发展史」空节（第 2 步拆书回填）            |

另外无论草稿拆分与否，必产 `原著/关系.md`：「关系总览」表格 `\| 角色 A \| 角色 B \| 关系类型 \| 情感倾向 \| 备注 \|`——前两列纯角色名且与 角色/ 文件名一致（前端人物关系网按表格解析）；表格后可加文字说明。

**回写进度**：落盘后 Edit \_progress.json（四步制 v2）：s1.status='done'、s1.substep='own'、meta 补全（title/author/totalChars），step 保持 1（第 1 步含原著+专属两个子阶段）。然后提醒：「原著设定完成。建议新开会话，输入『继续同人』进入专属设定（15 问）。」
